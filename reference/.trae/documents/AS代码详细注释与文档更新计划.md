## 注释规范

### 文件头部注释模板

```actionscript
// ============================================================
// 文件路径 - 功能简述
// ============================================================
// 功能说明：
// 本文件的主要功能和作用
// 
// 主要函数：
// - function1(): 功能说明
// - function2(): 功能说明
// 
// 数据结构：
// - 变量名: 类型 - 说明
// 
// 调用关系：
// 被调用者: _root.xxx
// 调用者: _root.yyy
// ============================================================
```

### 函数注释模板

```actionscript
// ------------------------------------------------------------
// functionName(param1, param2) - 功能简述
// 
// 参数：
// - param1: 类型 - 参数说明
// - param2: 类型 - 参数说明
// 
// 返回值：类型 - 返回值说明
// 
// 调用关系：
// - 调用: _root.xxx.function()
// - 被调用: _root.yyy
// 
// 算法说明：
// 详细的算法逻辑说明（如需要）
// ------------------------------------------------------------
function functionName(param1, param2)
{
   // 代码逻辑
}
```

### 行内注释规范

```actionscript
// 简单逻辑：单行注释
var hp = mhp;  // 恢复HP到最大值

// 复杂逻辑：块注释
/*
 * 伤害计算流程：
 * 1. 判定闪避
 * 2. 计算基础伤害
 * 3. 应用防御减免
 * 4. 应用战斗力修正
 */
```

## 文档更新规范

### 文档结构

1. **概述**：功能简介、文件位置、主要作用
2. **核心函数分析**：每个函数的详细说明
   - 函数签名
   - 参数说明
   - 返回值说明
   - 代码片段
   - 调用关系
3. **数据结构**：关键变量的说明表格
4. **流程图**：复杂逻辑的流程说明
5. **相关文件**：相关联的其他文件链接

### 表格格式

| 项目 | 说明 | 备注 |
|------|------|------|
| 变量名 | 类型 | 作用 |

## 执行策略

### 批量处理策略

由于文件数量众多（200+），采用以下策略：

1. **分类批量处理**：按功能分类，每类文件一起处理
2. **模板复用**：相似功能的文件使用相同的注释模板
3. **重点优先**：核心系统优先，UI组件次之
4. **文档同步**：代码注释完成后立即更新文档

### 质量保证

1. **注释准确性**：确保注释与代码逻辑一致
2. **文档完整性**：确保所有重要函数都有文档
3. **交叉验证**：通过调用关系验证注释正确性
