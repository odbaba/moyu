# 时间系统分析

## 概述

游戏采用独特的时间系统，将现实时间转换为游戏内的"天"和"时间单位"。玩家的每个行动都会消耗时间单位，当时间累积到一定值时进入下一天。游戏总时长为60天，玩家需要在这段时间内尽可能提升实力。

## 核心变量

### 时间变量

| 变量名 | 初始值 | 说明 |
|-------|-------|------|
| nowday | 1 | 当前天数（第几天） |
| onedaytime | 15 | 一天的时间单位总数 |
| nowtime | 0 | 当天已消耗的时间单位 |
| allday | 60 | 游戏总天数（在Flash UI中定义） |
| weekday | - | 当前星期几 |

## 时间系统核心函数

### reset() - 重置时间

```actionscript
function reset()
{
   nowday = 1;        // 重置为第1天
   onedaytime = 15;   // 每天15个时间单位
   nowtime = 0;       // 当天已用时间为0
}
```

### times_go(t) - 消耗时间

```actionscript
function times_go(t)
{
   nowtime += t;              // 增加已用时间
   if(nowtime >= onedaytime)  // 如果超过一天的时间上限
   {
      days_go(1);             // 进入下一天
   }
   upxx();                    // 更新界面显示
}
```

### days_go(d) - 天数增加

```actionscript
function days_go(d)
{
   nowday += d;     // 增加天数
   nowtime = 0;     // 重置当天时间
   upxx();          // 更新界面
   _root.nextday(); // 触发新的一天事件
}
```

### returnmap() - 返回地图时检查游戏结束

```actionscript
function returnmap()
{
   if(_root.mc_day.nowday > _root.mc_day.allday)
   {
      gotoAndStop("游戏结束");  // 超过60天，游戏结束
   }
   else
   {
      gotoAndStop(nowmap);      // 返回当前地图
   }
}
```

### 重置内容

| 重置项 | 说明 |

## 游戏结束判定

### 结束条件

- 游戏总时长：**60天**
- 当 `nowday > allday` 时，游戏结束
- 进入游戏结束评价界面（frame_37）

### 评价系统

游戏结束时根据以下指标进行评价：

| 评价项 | 最高评价 | 评价标准 |
|-------|---------|---------|
| 战斗力 | 终极勇士 | ≥1200 |
| 等级 | 冲级能手 | ≥132级 |
| 装备战斗力 | 装备打造宗师 | ≥126 |
| 幻兽战斗力 | 究极幻兽师 | ≥400 |
| 军衔 | 亚特兰蒂斯战神 | 元帅 |
| 爵位 | 人类的骄傲 | 王 |
| 公主关系 | 情圣 | 亲密恋人 |
| 财富 | 富可敌国 | ≥500000 |

## 时间单位换算

| 概念 | 数值 |
|-----|------|
| 1个时间单位 | 游戏内约1小时 |
| 1天 | 15个时间单位 |
| 1周 | 7天 |
| 游戏总时长 | 60天 = 约8.5周 |

## 时间管理策略

### 高效利用时间

1. **战斗选择**：选择高经验/高掉落的怪物战斗
2. **技能使用**：合理使用技能，避免体力浪费
3. **每日任务**：优先完成限时任务（如星期天的军饷）
4. **BOSS刷新**：关注每日BOSS刷新情况

### 时间消耗优先级

| 优先级 | 活动 | 时间消耗 |
|-------|------|---------|
| 高 | 主线任务战斗 | 3单位/场 |
| 高 | BOSS战 | 3单位/场 |
| 中 | 挖矿 | 1单位/次 |
| 低 | 抽奖 | 2单位/次 |

## 与其他系统的交互

- **存档系统**：保存/加载当前天数和时间
- **战斗系统**：每场战斗消耗3个时间单位
- **技能系统**：技能使用消耗体力
- **BOSS系统**：每日随机刷新
- **任务系统**：部分任务有星期限制

## 设计模式

时间系统采用了以下设计模式：

1. **单例模式**：全局唯一的时间管理器 `_root.mc_day`
2. **观察者模式**：天数变化触发 `nextday()` 事件
3. **策略模式**：不同活动消耗不同的时间单位
