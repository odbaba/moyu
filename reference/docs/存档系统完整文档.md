# 存档系统完整文档

## 概述

本游戏使用 Flash SharedObject 实现本地存档功能，存档系统位于 `DefineSprite_446` 中。存档名称为 `moyusave`，存储格式为 `.sol` 文件。

## 存档位置

- **Windows**: `%APPDATA%\Macromedia\Flash Player\#SharedObjects\`
- **存档文件名**: `moyusave.sol`

## 核心函数

### 1. savegame() - 保存游戏

### 2. beload() - 检查存档

检查存档是否存在且版本兼容。

**调用方式**：
```actionscript
_root.saveload.beload();
```

**检查流程**：
1. 获取 SharedObject 实例
2. 检查版本号是否匹配
   - 不匹配：清除存档
   - 匹配：继续检查
3. 检查 saved 标记是否存在
   - 不存在：显示加载失败，返回当前地图
   - 存在：设置标记，跳转到读取游戏流程

**版本兼容性检查**：
```actionscript
if(moyu_so.data.versions != _root.versions)
{
   moyu_so.clear();  // 版本不兼容，清除存档
}
```

### 3. loadgame() - 加载游戏

加载所有游戏数据。

**调用方式**：
```actionscript
_root.saveload.loadgame();
```

**加载流程**：
1. 清空当前背包、仓库、装备栏、幻兽背包
2. 加载地图和任务进度
3. 加载角色信息
4. 加载技能数据
5. 异步加载装备、背包、仓库、幻兽

## 异步加载机制

由于数据量较大，采用 `setInterval` 实现异步加载，避免界面卡顿。

### 加载顺序

```
loadgame()
    ↓
loaditem()     → 加载6个装备位（每30ms加载一个）
    ↓
loadbeibao()   → 加载背包物品（每30ms加载一个格子）
    ↓
loadcangku()   → 加载仓库物品（每20ms加载一个格子）
    ↓
loadhuanshou() → 加载幻兽（每30ms加载一只）
    ↓
chuzheng()     → 设置出征幻兽（每50ms设置一个）
    ↓
loaded()       → 加载完成
```

### 异步加载代码示例

```actionscript
function loaditem(dsc)
{
   if(++num > 6)
   {
      clearInterval(IntervalID);
      IntervalID = setInterval(loadbeibao, 30);
      return false;
   }
   // 加载装备逻辑...
}
```

## 存档流程图

### 保存流程

```
用户点击保存
    ↓
savegame() 被调用
    ↓
SharedObject.getLocal("moyusave")
    ↓
moyu_so.clear() 清除旧数据
    ↓
保存版本号 versions
    ↓
保存地图/任务/BOSS状态
    ↓
保存角色信息
    ↓
保存装备数据（6个位置）
    ↓
保存背包数据（二维数组遍历）
    ↓
保存仓库数据（二维数组遍历）
    ↓
保存幻兽数据（遍历幻兽背包）
    ↓
moyu_so.flush() 写入存档
    ↓
显示保存结果
```

### 加载流程

```
游戏启动
    ↓
beload() 检查存档
    ↓
版本检查 → 不兼容则清除存档
    ↓
存档存在检查 → 不存在则显示失败
    ↓
设置 _root.laoddata = true
    ↓
跳转到"读取游戏"帧
    ↓
loadgame() 被调用
    ↓
清空当前数据
    ↓
加载基础数据
    ↓
异步加载装备 → 背包 → 仓库 → 幻兽
    ↓
设置出征幻兽
    ↓
loaded() 加载完成
    ↓
跳转到当前地图
```

## 存档容量限制

SharedObject 默认大小限制：
- **默认**: 100KB
- **最大可请求**: 无限制（需用户授权）

当存档数据超过限制时，`flush()` 方法会返回 "pending"，需要用户授权更多存储空间。

## 版本兼容性

存档系统通过 `versions` 字段进行版本检查：

```actionscript
// 保存时
moyu_so.data.versions = _root.versions;

// 加载时
if(moyu_so.data.versions != _root.versions)
{
   moyu_so.clear();  // 版本不兼容，清除存档
}
```

**注意**：版本不兼容时，旧存档会被清除，玩家需要重新开始游戏。

## 设计模式

存档系统采用了以下设计模式：

1. **备忘录模式 (Memento)**: 保存和恢复游戏状态
2. **序列化模式**: 将对象转换为可存储格式
3. **原型模式**: 从存档数据重建对象
4. **异步加载模式**: 使用 setInterval 分批加载数据

## 注意事项

1. **数据完整性**: 保存前会先清除旧数据，确保不会有残留
2. **异步加载**: 加载过程分步进行，避免界面卡顿
3. **版本检查**: 版本不兼容会清除存档
4. **存储限制**: 需注意 SharedObject 的存储限制
5. **错误处理**: 存档不存在时会显示提示并返回当前地图
